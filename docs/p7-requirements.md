# P7 实施清单

来源：`11_七项目从零到发布执行指南` 第 6 步，以及 `07_对口开源项目清单与实施指南` 的 P7 卡片。下面按指南原文整理，用来对照交付，不替代指南。

## 目标

城市空气质量时空分析与交互式仪表盘。它是这组作品里「时空数据 + 可视化 + 部署」的完整闭环，部署后应能给出在线演示链接。

- 中文名：城市空气质量时空分析与交互式仪表盘
- 英文名：Urban Air Quality Spatiotemporal Analysis with Interactive Dashboard
- 仓库名：`air-quality-dashboard`
- 定位：主力项目，约两周
- 难度：★★☆☆☆

## 技术栈

指南写明的工具：

- Python
- pandas
- numpy
- scikit-learn
- Streamlit
- Folium
- streamlit-folium
- matplotlib
- seaborn

本仓库额外使用 scipy（层次聚类树状图与相关）、pyarrow（保存清洗结果）、requests（下载数据）。交互图使用 Streamlit 自带的 Altair。

## 数据集

北京多站点空气质量公开数据，2013–2017，12 个监测站，小时级。来源为 UCI / 论文配套数据，也可从公开镜像取得。

需要弄清的字段包括 PM2.5、PM10、SO2、NO2、CO、O3，以及露点、风速等气象量。

## 步骤

1. 环境准备  
   创建 `air-quality-dashboard`，建立虚拟环境，安装上述依赖。

2. 获取数据  
   下载 2013–2017 年 12 站小时数据，阅读数据字典。

3. 数据清洗  
   处理缺失值与异常值（按小时插值或剔除）。把 12 站合并成长表。检查时间范围和站点坐标是否完整。

4. 探索性分析  
   逐项完成，每一项至少一张图和一句结论：
   - 时间趋势（日 / 月均值曲线）
   - 季节模式（检验冬季是否更高）
   - 站点对比（各站年或全周期均值排序）
   - 气象关联（露点、风速与 PM2.5）
   - 极端污染日（超过阈值的天数）

5. 空间分析  
   - 按污染特征对站点做层次聚类
   - Folium 站点位置与热力
   - 用站点均值做简单空间插值，并和另一种空间估计对比（IDW）

6. 仪表盘  
   Streamlit 多页：
   - Overview：核心指标卡
   - EDA：趋势图 / 季节图
   - Visualization：Folium 地图
   - Advanced：聚类 / 关联
   - 城市与年份筛选

7. 部署上线  
   代码推到 GitHub 后，用 Streamlit Cloud 免费部署。在线链接应无报错、无乱码，加载少于 10 秒。  
   本轮按用户要求不执行 git commit / push，因此只准备部署配置和说明，不实际上云。

8. 发布收官  
   README 包含：简介、在线链接位置、仪表盘截图、数据来源与字段、本地运行步骤、至少 3 条有依据的结论、局限。表述为训练项目 + 公开数据集。

## 后续扩展（相对最初的北京卡片）

作品现在有两层：全国监测城市的日尺度，以及原来的北京 12 站小时尺度。全国层补充了 Moran’s I、LISA、区域季节对比，以及按时间切分的梯度提升树。监测表不是图像，也没有许可清楚的公开标注图像，所以没有 YOLO 检测页，不报告检测框或 mAP。面试备忘是 `docs/must-spatial-big-data-interview.pdf`。最初的 P7 验收（北京仪表盘、有依据的结论）仍然保留。
